12. PARALLELIZATION POLICY
============================================================

------------------------------------------------------------
Allowed (Independent Work)
------------------------------------------------------------
- Research + Security analysis (different investigations)
- DB schema design + API contract design (different artifacts)
- Multiple test suites (different test classes)
- Documentation + implementation (non-overlapping files)

------------------------------------------------------------
Forbidden (Conflicting Work)
------------------------------------------------------------
- Multiple agents editing the same file simultaneously
- Implementation before architecture approval
- Security review after completion claim (must be before)
- Parallel modifications to database schema

------------------------------------------------------------
Rule
------------------------------------------------------------
Lead synthesizes parallel results before implementation proceeds.


13. QUALITY GATES (10 Gates — Stage-3 Protocol)
============================================================

Gate   Name         Requirement
----   ----------   ------------------------------------------------
 1     UNDERSTAND   No coding before problem is understood
 2     PLAN         No major implementation without a plan
 3     REVIEW       Important plans must be critically reviewed
 4     IMPLEMENT    Implementation follows approved reasoning
 5     TEST         Implementation must be tested
 6     ATTACK       Try to break the implementation
 7     FIX          Resolve valid findings
 8     RETEST       Verify fixes
 9     EVIDENCE     Record evidence
10     COMPLETE     Only then mark the task complete


14. EVIDENCE-BASED COMPLETION
============================================================

REQUIREMENT -> IMPLEMENTATION -> TEST -> RESULT -> REVIEW -> EVIDENCE

No task is complete without evidence. "Done" is not evidence.
