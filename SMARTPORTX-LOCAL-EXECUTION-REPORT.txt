6. REMAINING ISSUE: PROMETHEUS SCRAPE TARGETS
---------------------------------------------

Prometheus is running and its own target is healthy. Current scrape results:
  - 10 active targets total.
  - 1 target up: Prometheus itself (`localhost:9090`).
  - 9 targets down.
  - Eight service targets return HTTP 401.
  - The gateway target returns HTTP 404.

Cause observed:
  - Spring security on application service actuator paths requires
    authentication except for selected health/info endpoints.
  - The current Prometheus scrape configuration does not supply credentials.
  - The gateway's actuator exposure is configured for health, info and
    metrics; `/actuator/prometheus` is not exposed, so the scrape path returns
    404.

No authentication or authorization was disabled, and no service was marked
healthy to hide this issue. To resolve it, the project needs a deliberate
metrics access design, such as a restricted scrape endpoint or a supported
authenticated Prometheus scrape configuration, plus exposing the gateway
Prometheus endpoint. This was not changed during the local startup task.

To register/connect the Docker database in pgAdmin:
  1. In pgAdmin, right-click Servers and choose Register > Server.
  2. On General, enter a display name such as `SmartPortX Docker`.
  3. On Connection, enter:
       Host name/address: localhost
       Port:              5433
       Maintenance DB:    smartportx
       Username:          smartportx
       Password:          smartportx_local
  4. Save the password only if appropriate for this local machine, then Save.
  5. Expand Servers > SmartPortX Docker > Databases > smartportx > Schemas.
  6. Expand a service schema (for example `smartportx_container`,
     `smartportx_vessel`, or `smartportx_yard`) > Tables.
  7. To inspect rows, right-click a table and choose View/Edit Data > All Rows.

Use port 5433 for the Docker database. Port 5432 belongs to the existing
local PostgreSQL process and may open a different database instance.
The Compose development credentials above were checked against this running
Docker database; do not use them for production.

To confirm the frontend persistence test account in pgAdmin, open
`smartportx_identity.users` and filter for username
`frontend_db_check_20261030`. The account is disabled (`enabled=false`).
